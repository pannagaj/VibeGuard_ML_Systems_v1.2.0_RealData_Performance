# Real-data experiment plan and evidence rules

VibeGuard has two different data tracks. They must not be conflated in resumes or technical
reports:

1. `data/motor_vibration.csv` is generated by a deterministic synthetic simulator. It tests the
   software pipeline, not industrial model quality.
2. `experiments/cwru_benchmark/` is designed to download measured laboratory vibration from the
   official CWRU Bearing Data Center and evaluate cross-load transfer on held-out 3 HP recordings.

The second track requires downloading the 16 original `.mat` files from the source host and running
the experiment. It has not been executed against downloaded CWRU data in a network-restricted build
environment. Until the user runs it, no CWRU accuracy, F1, latency, or throughput result may be
quoted as an achieved result.

## Commands

```bash
python -m pip install -e '.[dev,realdata]'
python -m experiments.cwru_benchmark.prepare
python -m experiments.cwru_benchmark.train
python -m experiments.cwru_benchmark.profile
pytest -q
ruff check .
ruff format --check .
```

## What to save after running

- `data/cwru/dataset_manifest.json`
- `artifacts/cwru/cwru_evaluation.json`
- `artifacts/cwru_profile/cwru_profile_report.json`
- `artifacts/cwru_profile/torch_profiler_summary.txt`
- `artifacts/cwru_profile/torch_profiler_trace.json`
- A commit containing the final reviewed code and a filled coding-agent run log.

## Scope limitations

CWRU uses an instrumented lab rig and seeded faults, not uncontrolled field conditions. The split
holds out a motor load, not an independently sourced motor or sensor installation. It can provide
real measured-signal ML evidence but does not prove production predictive-maintenance readiness.
